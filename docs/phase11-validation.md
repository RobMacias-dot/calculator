## Methodology and evidence boundaries

Reviewed every registered definition, all 44 modes, the corresponding pure solvers, parsing, unit conversion, report construction, formatting, shared ViewModel, form fields, ResultCard, eight visual mappers/renderers and Playground composition. Reviewed titles, descriptions, input labels/symbols and search keywords against their actual operations. Used dimensional reasoning and hand-worked references rather than treating passing tests as mathematical proof.

Executed every mode with explicit canonical inputs and inspected its emitted formula, normalized substitution, value/unit, details and explanation (`build/phase11-catalog-audit.json`, regenerated by local `build/phase11-audit.dart`). The persistent fixture is `test/support/catalog_audit_samples.dart`; it extends the existing independently tabulated Phase 4 numeric samples. A new state-contract test visits every fixture, empties each field, restores validity, changes every offered alternative input unit, switches modes and resets. The unit round-trip test is a state/normalization property, not an independent proof of each conversion constant; factors were also inspected and checked against reference values.

The original seven defect regressions failed before fixes: 247/254 domain cases passed (`build/phase11-regressions-before.log`). After fixes they passed 254/254. An eighth case was subsequently added to check operand round-trips over zero, signed, near-equal, small, large, subnormal and maximum finite values. Existing tests already exercise decimal commas, exponent syntax, nonfinite values, overflow/underflow, model boundaries, signed physical quantities, affine temperatures, alternate units and networking boundaries. New tests target the exposed gaps.

This is a source, domain, state and targeted UI audit, not a claim of physically testing each screen on each Android API. Native validation is limited to the existing API 37 emulator because only Dart content/numerics changed. Phase 10 remains the source for the API 24/30/37 and bundletool/split-install matrix.

## Mathematical and dimensional findings

F2 is the only changed mathematical implementation. An exact factored polynomial provides independent evidence: x²−10x+25=(x−5)², so a positive-discriminant narrative is wrong. Power-of-two scaling avoids introducing the arbitrary-max division error; stable q-based roots, range guards and exact sign branches remain. Neighboring coefficients on both sides of D=0 are tested to prevent an epsilon-based false repeated root. All other reviewed relationships agree with their stated engineering models; no reversed ratios, missing squares, wrong constants or mode inversion were found in the reviewed cases.

Dimensional checks, performed manually:

| Family | Dimensional reasoning |
|---|---|
| Electrical | V/Ω=A; VI=W; W·s=J; resistor ratio in divider dimensionless; series/parallel return Ω |
| Mechanics | kg·m/s²=N; N·m is torque or work according to the stated phenomenon; J/s=W; kg·(m/s)²=J; kg·m/s momentum |
| Fluids | kg/m³·m/s·m divided by Pa·s is dimensionless; m²·m/s=m³/s; ρgh and ρv² are Pa; every Bernoulli summand is pressure |
| Thermal | nRT has Pa·m³; kg·J/(kg·K)·ΔK=J; Wout/Qin dimensionless; α·L·ΔT=m; absolute temperature offsets do not apply to intervals |
| Mathematics / networking | percentages use dimensionless ratios; Pythagorean lengths share a dimension; vector components share implicit units; polynomial coefficients are entered as abstract scalars; networking uses exact bit/integer counts |

Constants and conventions checked against primary references: standard g=9.80665 m/s², atmosphere=101325 Pa, bar=100000 Pa, litre=.001 m³, Wh=3600 J, and affine absolute temperature vs interval conversions agree with [NIST SP 811 Appendix B.9](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9). The molar gas constant is R=N_A k=8.31446261815324 J/(mol·K), using the defined N_A and k values in [NIST CODATA constants](https://physics.nist.gov/cuu/Constants/Table/allascii.txt). The /31 point-to-point treatment agrees with [RFC 3021](https://www.rfc-editor.org/rfc/rfc3021.html); it is explicitly conditional on that convention, not a guarantee of real-world routability.

Floating-point cancellation was checked against the numerical issues described in [Goldberg, reproduced in Oracle's Numerical Computation Guide](https://docs.oracle.com/cd/E19422-01/819-3693/ncg_goldberg.html). The implemented change is justified by the reproduced integer polynomial and neighboring-root regressions; that reference is not a claim that this small solver provides arbitrary-precision or universally correctly rounded discriminants.

## Units and numerical presentation

No incorrect conversion factor or quantity dimension was found. All offered alternative input units were exercised through their mode's state/normalization pipeline. Existing independent fixtures cover milli/kilo/mega electrical units, g/kg, cm/mm, cm², litre, Pa/kPa/bar/atm, W/kW, J/kJ/Wh/kWh, second/minute/hour, L/s/L/min, specific heat, expansion coefficient and percent scaling. Temperature conversion tests distinguish absolute K/°C/°F from ΔK/Δ°C and test absolute zero; the gas law correctly excludes zero Kelvin while the converter permits it.

Input unit selection intentionally **preserves the typed numeric magnitude** and changes its unit. Example: typing 1 and choosing kV means 1 kV, not a hidden conversion of 1 V. The visible selector identifies that unit; ordinary forms immediately remove the old report and require Calculate, while Playgrounds recalculate from the new pair. This existing behavior was preserved. Slider edits convert their SI value into the currently selected input unit before using the same pipeline. No stale explanatory text survives a unit change.

F1 separates operand fidelity from result rounding. `NumberFormatting.operand` first tries the existing compact form, retains it only if parsing it recovers the normalized double, otherwise uses the double's shortest round-trip string. It is used only for normalized operands/input descriptions and visual input labels. No displayed string is fed back into a solver. The same fix covers cancellation in Bernoulli and small multiplicative inputs, not just the three original reproductions.

Ordinary scalar outputs retain the existing six-decimal policy, trimming zeros and using scientific notation below 1e−6 or at/above 1e9. Zero displays as 0; signed meaningful results retain their sign. This is display rounding, not a significant-figure/uncertainty model: the fixed-decimal interval has absolute rounding error up to about 5e−7 in the displayed unit and can have large relative rounding error near its lower end. Full domain values remain available internally; this audit does not claim a guaranteed relative display precision. No speculative global precision policy was introduced. F3 instead makes the narrow, demonstrable exception for two distinct quadratic roots that would otherwise print identically. Their full values are displayed only when that collision occurs. Complex imaginary parts remain nonzero under the existing scientific-notation rule.

Longer operand text is intentional when needed to preserve the mathematical statement. The changed quadratic substitution was exercised at 320 px/200% text, including semantics and Copy; the full existing large-text, theme, visual and Playground suites also pass.

## Validation findings and invalid-input policy

F4 corrected a real mismatch between input guidance and the integer-prefix parser. No domain restriction was tightened. Numeric missing input, malformed/nonfinite input, unrepresentable magnitude, forbidden zero, negative physical quantities, incompatible units and invalid ranges continue through their existing issue paths. Malformed and explicitly nonfinite numeric strings share the concise finite-decimal guidance; their internal error codes remain distinct. Binary IPv4 missing input uses its existing four-eight-bit-groups guidance rather than a separate required-field sentence. Both are actionable and do not produce a result.

Signed values remain valid for voltage/current/DC power under the stated passive convention, acceleration/force, mechanical work/power, velocity/momentum/flow, Bernoulli pressure/elevation, heat/temperature differences, expansion coefficients, percentage operands, vector components and polynomial coefficients. Speed and magnitude-only torque inputs deliberately differ from signed velocity/axis force. Ideal-gas state variables are absolute and positive. Efficiency is restricted to heat-engine work output, not refrigeration COP. Linear expansion rejects a nonpositive final length and states its small-strain assumption instead of inventing an arbitrary physical cutoff.

Ordinary forms immediately clear result/substitution/Copy/visual availability when edited; field validation appears on the next Calculate, consistent with their existing submit-based interaction. Live Playground edits invoke that same calculation immediately, so validation and removal happen together. The mode formula and general educational description may remain while awaiting valid input; neither is an old result. The new all-mode test verifies invalidation, missing-field validation and recovery for every field, including structured IPv4/quadratic results and resistance lists. Existing tests cover malformed/domain-invalid values and live visual invalidation.

## Reset, Copy and modes

No global Reset redefinition was needed. Visual sheets use the same ViewModel and stop showing a scene when its report disappears. Playground has its established edit/back interaction rather than a newly added reset action; returning to the ordinary form uses that same borrowed ViewModel.

Copy is implemented once in `CalculationResultSummary`, used by both ordinary results and Playgrounds. It serializes the active immutable report at the time of the press. Ordinary numeric labels derive from the formula's left side; explicit labels handle quadratic Roots and networking outputs. The converter's existing K-labelled output is tied to its kelvin conversion relation. Copy includes units once with the result and normalized units in substitution, and is absent without a valid report. ## Phase 11 decision

The baseline did contain concrete content/presentation defects that should be corrected before expansion: rounded operands could describe a different mathematical problem, arbitrary quadratic scaling could misclassify an exact repeated root, and distinct roots could print identically. Those defects and the two smaller copy issues are now corrected. Within the stated model, floating-point and presentation limits, the 30 existing calculators form a coherent engineering-learning toolkit across input, validation, normalization, domain result, formula, substitution, explanation and existing visual/Playground presentation. This conclusion is supported by the 44-mode audit and focused before/after regressions; it is not an assertion of unlimited numerical accuracy or public-release readiness.

Phase 11 ends with this report. No Phase 12 functionality was implemented.
